# Waqt

Виджет времени намаза для Windows (Electron): окно 200×200 поверх всех окон, таймер до конца намаза, отметки прочитанных, история, синхронизация с Supabase.

Источники истины: спецификация `docs/superpowers/specs/2026-09-30-waqt-design.md`, тикеты `.scratch/waqt/issues/` (порядок и блокировки указаны в каждом файле). Стиль виджета: `sajda.png`, вид истории: `example.png`.

## Правила
- Общаться и комментировать на русском; идентификаторы кода на английском.
- Секреты только в `.env` (в `.gitignore`). Используется только publishable key Supabase. Secret key и пароль БД не использовать и не записывать никуда.
- Логику (`computeState`, напоминания, слияние отметок) писать чистыми функциями и покрывать тестами вперёд реализации.
- UI и звук проверять запуском приложения; подменять время для проверки красных состояний.
- Репозиторий `https://github.com/imangali01/waqt.git`, основная ветка `main`. Каждая фича/задача плана в отдельной ветке от актуального `main` (`feat/<имя>`), после проверки push ветки и merge в `main` через git (gh не используется). Push разрешён пользователем без отдельного подтверждения; force-push запрещён.
- Параллельные тикеты вести в отдельных git worktree.
- Итог проекта: установщик Windows (electron-builder, NSIS) и git-тег `vX.Y.Z` (ветка `release/vX.Y.Z`); GitHub Release с файлом установщика создаёт пользователь вручную. План: `docs/superpowers/plans/2026-09-30-waqt.md`.
- Красный статус не хранится, а вычисляется. Красный можно превратить только в жёлтый.

## Флоу
1. Тикет 01 делается один. Затем до 2 параллельных потоков (03 и 06; 07 и 08).
2. Реализация в основной сессии (Sonnet). Ревью агентом `reviewer` (Opus) после тикетов 03, 07, 08.
3. Сбор данных для тикета 05 агентом `names-collector` (Haiku).
4. Перед закрытием тикета: тесты зелёные, приложение запущено и проверено.
