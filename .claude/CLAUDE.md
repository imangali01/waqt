# Waqt

Виджет времени намаза: десктоп (Electron, Windows и macOS) — маленькое окно поверх всех окон (режимы размера `full`/`compact`/`medium`/`strip`), таймер до конца намаза, звук и азан, отметки прочитанных, история, синхронизация с Supabase. Плюс веб-версия для iPhone («На экран Домой») с push и виджет Scriptable.

Обзор и команды — `README.md`. Исторические документы (на момент старта, виджет 200×200): спецификация `docs/superpowers/specs/2026-09-30-waqt-design.md`, план `docs/superpowers/plans/2026-09-30-waqt.md`, закрытые тикеты `docs/archive/issues/`. Стиль виджета: `docs/design/sajda.png`, вид истории: `docs/design/example.png`.

## Правила
- Общаться и комментировать на русском; идентификаторы кода на английском.
- Секреты только в `.env` (в `.gitignore`). Используется только publishable key Supabase. Secret key и пароль БД не использовать и не записывать никуда.
- Логику (`computeState`, напоминания, слияние отметок) писать чистыми функциями и покрывать тестами вперёд реализации.
- UI и звук проверять запуском приложения; подменять время для проверки красных состояний.
- Репозиторий `https://github.com/imangali01/waqt.git`, основная ветка `main`. Каждая фича/задача плана в отдельной ветке от актуального `main` (`feat/<имя>`), после проверки push ветки и merge в `main` через git (gh не используется). Push разрешён пользователем без отдельного подтверждения; force-push запрещён. После merge в `main` и push сразу удалять ветку: удалённую (`git push origin --delete <ветка>`), локальную (`git branch -d`) и worktree задачи (`git worktree remove`), если он был. Удалять только ветки, уже влитые в `main`.
- Параллельные задачи вести в отдельных git worktree.
- Релиз: установщик Windows (electron-builder, NSIS) и git-тег `vX.Y.Z` (ветка `release/vX.Y.Z`); GitHub Release с файлом установщика создаёт пользователь вручную.
- Красный статус не хранится, а вычисляется. Красный можно превратить только в жёлтый.
- Установщик `Waqt-Setup-*.exe` без цифровой подписи блокирует Windows 11 Smart App Control. Для раздачи используется пакет `npm run pack:win` → `dist/Waqt-<версия>-win.zip` (папка приложения + `Install.cmd`/`Uninstall.cmd`, скрипты cmd только с CRLF, см. `.gitattributes`). Настоящее решение — подпись сертификатом.
- macOS: собирается только на macOS (`npm run dist:mac`, universal dmg+zip), локально с Windows нельзя; сборку делает GitHub Actions (`.github/workflows/build.yml`, вручную или по тегу `v*`, секреты `SUPABASE_URL` и `SUPABASE_PUBLISHABLE_KEY`). Без подписи Apple первый запуск: правый клик → «Открыть» (или `xattr -cr Waqt.app`). Виджет для iPhone: `scripts/scriptable/Waqt.cjs` (приложение Scriptable), позднее нативный SwiftUI+WidgetKit.
- Сайт: `site/` (лендинг + веб-версия виджета `site/app/` для «На экран Домой» в Safari). Общий код копирует `npm run site:build` (сгенерированное в .gitignore), сайт задеплоен на Vercel (https://waqt-timer.vercel.app), инструкция по деплою — `docs/deploy-vercel.md`. Push-уведомления на телефон: `docs/web-push.md`. Имена файлов релиза фиксированные (`Waqt-Setup.exe`, `Waqt-mac.dmg`), чтобы ссылки `releases/latest/download/...` на лендинге работали.
- Приложение допускает один экземпляр на пользователя: если уже запущена другая сборка, новый запуск сразу закрывается.

## Команды и порядок работы
- `/rebuild` (`.claude/commands/rebuild.md`) — пересобрать десктоп-приложение в `dist/`. После любых изменений десктопного приложения (`src/`, `assets/`, `package.json`) предлагать запустить `/rebuild`.
- `/deploy` (`.claude/commands/deploy.md`) — деплой сайта на Vercel по `docs/deploy-vercel.md`. После любых изменений сайта (`site/`, общего кода `src/core/`, `src/web/`, `assets/`, влияющего на веб-версию) предлагать запустить `/deploy`.
- После каждого визуального изменения (виджет, сайт, история) показывать скриншот с тем, что изменилось: перед созданием новых скриншотов очищать папку `.screens/` (удалить старые файлы), затем сохранять новые только туда (папка в .gitignore) и отправлять в чат ссылкой-картинкой `![подпись](.screens/имя.png)` плюс кликабельной ссылкой на файл (пользователь не видит результат Read). Виджет рендерить в headless Edge (`msedge --headless=new --screenshot`) на реальной разметке `src/renderer/index.html` с подставленным `window.waqt`, сайт — так же по локальному серверу; запущенный Waqt блокирует второй экземпляр Electron. Показывать нужные состояния (обычное, красное, отмеченный и т. п.). В ответе указать, что это скриншот, а не живое приложение.
- По завершении каждого изменения автоматически делать коммит и push (без отдельного подтверждения; правила веток выше сохраняются, force-push запрещён).
- Ревью заметных изменений логики, синхронизации, IPC и push — агентом `reviewer`.
- Перед merge: тесты зелёные (`npm test`), приложение запущено и проверено; при правках `src/core/`/`src/web/` — `npm run site:build` проходит.

## Настройка .env (создаёт пользователь, Claude не читает и не пишет `.env*`)
В корне проекта файл `.env`:
```
SUPABASE_URL=https://xzmezgwdwqrfgbhxgdsu.supabase.co
SUPABASE_PUBLISHABLE_KEY=sb_publishable_...   # Publishable key из Project Settings → API Keys
```
Таблицы создаются запуском `supabase/schema.sql` в SQL Editor. Для проверок можно передать те же переменные через окружение процесса, не трогая файл.
